# ToyScope layers and migration

[English](TOYSCOPE.md) | [Polski](TOYSCOPE.pl.md)

## Classification

| Documents | Layer and status |
| --- | --- |
| `sema/examples/toyscope_N/toyscope_N.coge`, N = 1, 2, 3 | Authored format 1 sources: grammar, analysis, and the retained execution contract |
| `toyscope_N.sema` beside each source | Generated analysis projections, without an execution contract |
| `toyscope_N.sema.provenance.json` | Export metadata: source, hashes, runtime contract, and origin maps |
| `generated/projections/toyscope_N.ag` and manifests inside each example | Grammar exports; they do not overwrite the canonical legacy grammar |
| `sema/examples/scope_codegen/scope_codegen.sema` | Analysis-only document using the explicit legacy path |
| `tests/fixtures/legacy/scope_codegen_bad_*.sema` | Negative legacy analysis fixtures |
| `tests/fixtures/legacy/toyscope_N.sema.txt` | Historical mixed sketches requiring conversion |

The typed sources cannot be authored `.sema` documents because they contain
`execution_contract`. The full description lives in `.coge`, and `.sema` is
produced through the official projection. Specification names, analysis
actions, and execution contracts are preserved. Projections must not be
edited manually. Historical prose sketches excluded from the import are
not format 1 CLI inputs.

## Working path

The analyzer is generated by `sema`, which does not link the executor library.
The explicit [runtime contract](../../contracts/toyscope-runtime-v1.json)
describes Rust types shared by all three policies. These types are opaque;
intrinsic functions and signatures are declared explicitly in the sources.
The contract is not inferred by scanning Rust.

```sh
cmake --build build --target sema coge ag -j4
build/bin/sema --check \
    --contracts contracts/toyscope-runtime-v1.json sema/examples/toyscope_1/toyscope_1.sema
python3 tools/regenerate_examples.py toyscope_1 toyscope_2 toyscope_3
```

Regeneration first exports `.sema` and `.ag` through `coge`, then generates
analysis from the clean projection through `sema` and a parser from exported
Ag. It refreshes projections, manifests, and Rust baselines. `--sema-cli`
selects the analysis binary; `--coge` selects the projection binary. The old
`--sema` argument remains an alias for `--coge`.

The executor remains handwritten in
`sema/examples/toyscope_1/src/execute.rs`, with policies 2 and 3 using the
same runtime. Likewise, `scope_codegen/src/ir_exec.rs` is a handwritten IR
executor; its presence in a Rust package does not change ownership of an
analysis-only document.

## Executor conversion

Retained `execution_contract` sections still use historical actions such as
`require ... else reject_execution`, `with ... finally`, frame creation, and
implicit runtime access. They are not ready for format 1 executor generation.
`coge --check` currently reports `coge.invalid_contract` with
`unsupported execution statement: requireStatement`. Analysis export is valid
and independent of this unsupported part.

Full conversion requires an explicit `execution_model`: frame and state types,
frame creation/release functions, reads/writes, errors, effects, and contracts
rewritten as supported actions. Preserve the policy differences: initializer
state in policy 1, binding after initialization in policy 2, and reservation
of names/state in policy 3. Confirm executor readiness against independent
Rust tests for each policy.

Historical `.sema.txt` files also require conversion of unsupported queries,
rewrites, and `execution result`. They are sketches for conversion, not
working generated interpreters.

## Verification

`agsem_toyscope_layer_tests` checks analysis export, saved projections, rejection
of `.coge` by `sema`, the explicit executor limitation, checking `.sema` after
removing its `.coge` source, and Ag export. The three
`sema_toyscope_*_typed_codegen` tests compare analyzers and parsers with saved
baselines. Rust tests verify all three policies.
